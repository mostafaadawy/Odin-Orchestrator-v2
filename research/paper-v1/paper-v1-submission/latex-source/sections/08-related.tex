\section{Related Work}\label{sec:related}
\paragraph*{Why multi-agent systems fail} The MAST study analyses execution traces of seven multi-agent frameworks and attributes failures to specification issues, inter-agent misalignment and task verification~\cite{cemri2025mast}; it argues that many failures are organisational rather than model limitations. \sys{} is a practitioner's answer to the organisational part: structure is enforced by construction rather than requested in prompts. Multi-agent frameworks such as AutoGen, MetaGPT and ChatDev~\cite{wu2023autogen,hong2024metagpt,qian2024chatdev} coordinate roles within one task; they do not govern a shared, multi-owner workspace.

\paragraph*{Reuse of agent skills (F1--F3, F7)} Skill and workflow libraries let agents reuse code they wrote before~\cite{wang2023voyager,wang2024awm,wang2025asi,yu2026polyskill}; SkillOps manages such a library as a self-maintaining ecosystem~\cite{pu2026skillops}; tool retrieval selects among many APIs~\cite{patil2024gorilla}; plan and semantic caches reuse earlier answers~\cite{zhang2025apc,fu2023gptcache,gill2025meancache}; case-based reasoning frames reuse in general~\cite{aamodt1994cbr,hatalis2025cbr}. \sys's base-plus-delta discipline is the component idea~\cite{mcilroy1968components,react} and delta-oriented programming~\cite{schaefer2010delta}, re-discovered for agent scripts; what it adds is a single creation door and a database that is the only registry across \emph{many owners' projects}.

\paragraph*{Routing (F2)} Model routers trade cost for quality~\cite{ong2025routellm}; \sys{}'s agents choose between reuse, delta and new work by reading a registry view, while placement stays rule-based; sentence embeddings are only proposed (Section~\ref{sec:proposals}).

\paragraph*{Sync, queueing and callbacks (F4--F6)} Local-first software and CRDTs give strong convergence guarantees~\cite{kleppmann2019localfirst}; \sys{} uses the simpler combination of a durable mirror and per-scope sequence numbers in the spirit of logical clocks~\cite{lamport1978time}. Its pulled queue is a minimal message broker~\cite{vinoski2006amqp}, and its callbacks follow industry webhook practice with retries until acknowledgement~\cite{stripewebhooks}.

\paragraph*{Deployment and CI (F8--F10)} Zero-trust access~\cite{ward2014beyondcorp} removes reliance on network location; \sys's dynamic-IP firewall instead keeps a single current address allowed for operators without a static IP. Change-based deployment relates to regression test selection by file dependencies~\cite{gligoric2015ekstazi}, and the self-healing deploy agent to LLM-based repair agents~\cite{bouzenia2025repairagent}.

\paragraph*{Conformance and guardrails (F11)} Reflexion models check source against an intended architecture~\cite{murphy1995reflexion}; \sys's audit applies the same idea to the artefacts that agents create, and heals deviations. Runtime enforcement for agents~\cite{wang2026agentspec}, programmable rails~\cite{rebedea2023nemo} and capability-based designs~\cite{debenedetti2026camel,saltzer1975protection} constrain actions. \sys's pre-tool hook (Section~\ref{sec:p2}) is a runtime check of this kind, but it adds no rule language of its own: it calls the same router as the creation door. The truth gate addresses part of the verification failures reported by MAST.
