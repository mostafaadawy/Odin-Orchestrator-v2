\begin{abstract}
As agentic systems grow from single tasks into ecosystems of many projects, each with its own team of LLM agents, the hard problem becomes keeping the whole system consistent. Files must land where they belong, no project may depend on or overwrite another, there must be one source of truth, and no ``done'' may be false. We present \sys{}, a multi-project agentic ecosystem built and operated by one engineer with agents. Each of its eleven features was forced by a concrete failure, which we reconstruct from the system's own logs. Consistency is enforced \emph{by construction}: one creation door checks placement and owner scope on every write, a database is the only registry, and an audit checks and heals at rest. We measure on an isolated copy of the production system and report ratios. A scripted workload demonstrates the mechanism: through the door, violations stayed at 0 for 1 to 10 concurrent projects, against 22--31\% without it. The main evidence comes from real LLM agents. Our first measurement exposed a gap: files that agents wrote with their own tools bypassed the door, and correct placement fell from 67\% to 17\% as projects were added. We closed the gap inside the isolated copy with two changes that add no new rule. First, agents now start in their own project folder. Second, a pre-tool hook applies the existing owner-scope rule to the agents' own writes and sends shared writes through the door. Re-running the same experiment, correct placement became 100\% at every scale, task success rose from 52/54 to 54/54, and no file landed outside its project. When agents were told to write into shared code and into another project, the hook blocked every raw attempt; the agents then used the door. The same work fixed two defects found by the owner's own tests. A regression suite of 32 checks passed with no regressions.
\end{abstract}
