# Odin — Anchor Connect + Klaviyo/Veeqo Integrations (Phases 1–2)

This README covers everything built around **external access** and **operational integrations**:

- **Klaviyo (Email)** + **Veeqo (Shipping/Fulfillment)** API integrations.
- **Anchor Connect** — the external access layer (queue + auth + webhooks) that lets third parties
  and your own remote app reach local projects.
- The **odin_app** Flutter client (web + iOS + Android) that mirrors the desktop.
- The **third‑party simulator** and the **deployed‑anchor stand‑in** used to test the Phase‑3
  topology now.

> **TL;DR — one command to bring it all up and test:**
> ```bash
> cd <odin-repo-root>
> ./phase2_up.sh
> ```
> Then jump to **[Commands to test](#commands-to-test)**.

---

## What runs where

| Component | Where | What it does |
|---|---|---|
| **Brain** | `http://localhost:8000` | Local AI + dashboard API + agents (CTO→team). Holds projects/chat/data. Serves the old console at `/`. |
| **Desktop app** | Electron window (uses `:8000`) | The original rich dashboard. |
| **Web app** (Flutter) | `http://localhost:8080` | You, remotely — mirrors the desktop + the Anchor page. Dark, branded "Remote Anchor · Web". |
| **Mobile app** (Flutter/iOS) | the phone/simulator | Same app, mobile layout. |
| **Anchor** (stand‑in for the VM) | `http://localhost:9100` | Queue + auth + webhooks. The door third parties knock on. |
| **Local poller** | no port | Pulls tasks from the anchor over HTTP → runs CTO→team on the brain → posts results. |
| **Third‑party simulator** | `third_party_sim.html` / `server/third_party.py` | Pretends to be an outside app sending a prompt. |

**Flow:** `simulator → anchor(9100) → local poller → brain(8000) runs CTO→team → result → anchor → webhook to caller`.
Web/Mobile/Desktop all read/act on the same Brain(8000).

---

## Phases

- **Klaviyo / Veeqo integration** — full read/write API clients; Email + Shipping agents; Email &
  Fulfillment project types. Testing is **read‑only** (GET) so it never changes your accounts.
- **Anchor Phase 1** — smart queue + lifecycle + webhook delivery + ack + retry, with the
  in‑process anchor and three E2E suites. Contract in `ANCHOR_CONTRACT.md`.
- **Anchor Phase 2** — the Flutter app (shared web+mobile), the deployed‑anchor stand‑in
  (`anchor_remote.py`), the HTTP local poller (`local_poller_http.py`), the topology E2E
  (`e2e_phase2.py`), the third‑party simulator, generated test keys, and the shared chat pool.
- **Anchor Phase 3** (next, not done) — Dockerize the anchor + systemd, TLS on the VM, serve the
  web build same‑origin, signed webhooks.

## Commands to test

### 0) Bring everything up (recommended)
```bash
cd <odin-repo-root>
./phase2_up.sh
# prints the test keys, starts brain(:8000) + anchor(:9100) + poller + desktop + web(:8080) + iOS sim
# OPEN_DESKTOP=0 ./phase2_up.sh   # skip launching the desktop if you run it yourself
```

### 1) Klaviyo / Veeqo + Anchor Phase 1 (the 3 suites)
```bash
python3 server/e2e_anchor_all.py
# 1. logic lifecycle      (runs anywhere)
# 2. HTTP contract        (needs fastapi)
# 3. live read-only data  -> prints your REAL numbers:
#      Klaviyo flows: total=50  by_status={live:28, draft:22}
#      Veeqo orders this week: 26
```
Run a single suite:
```bash
python3 server/e2e_anchor.py          # logic + webhook + retry + fail
python3 server/e2e_anchor_http.py     # /anchor/v1 endpoints + auth
python3 server/e2e_anchor_live.py     # real Klaviyo/Veeqo via the CTO→team orchestration
```

### 2) Anchor Phase 2/3 topology (app ⇄ remote anchor ⇄ local)
```bash
python3 server/e2e_phase2.py --smoke  # fast: HTTP + queue + webhook + ack (runs anywhere)
python3 server/e2e_phase2.py          # REAL: remote round-trip + CTO→team + real numbers
```

### 3) Manual: run the deployed-anchor stand-in + poller yourself
```bash
# terminal A — the stand-in 'deployed' anchor
python3 server/anchor_remote.py --port 9100
# terminal B — your Mac polling it over HTTP (real orchestration)
python3 server/local_poller_http.py --anchor http://localhost:9100
```

### 4) Act as a third party (the missing puzzle piece)
First get a real project id (the anchor targets a project that exists on the brain):
```bash
curl -s http://localhost:8000/projects | python3 -m json.tool | grep '"id"'
```
Then either:
```bash
# CLI
python3 server/third_party.py --anchor http://localhost:9100 \
  --project <PROJECT_ID> --prompt "How many orders did we get this week?"
```
or open **`third_party_sim.html`** in a browser and fill:

| Field | Value |
|---|---|
| Anchor URL | `http://localhost:9100` |
| X-API-Key | *(optional — intake/status are open)* the `ANCHOR_API_KEY` |
| Target project id | a real id from the curl above (e.g. an Email or Shipping project, or `organics`) |
| Prompt | `How many flows are live vs draft?` / `How many orders this week?` |

> The answers you already know — **50 flows (28 live / 22 draft)** and **26 orders this week** —
> confirm the full chain is genuinely connected if they come back matching.

### 5) The Flutter app
```bash
# web (served by phase2_up at :8080), or build/run manually:
cd odin_app
flutter create . --platforms web,android,ios --project-name odin_app --org com.odin
flutter pub get
flutter run -d chrome        # web
flutter run -d <ios-id>      # iOS (flutter devices to list)
```
In the app: **Settings** → pick a profile (`Local (Phase 2)` for same‑network, `Anchor sim` to go
through `:9100`), paste keys if set, **Test connection**. New project via **＋ New**. Chat uses the
shared `/scope` pool (persists, same conversation as desktop). 🔊 reads replies, 🎤 dictates.

## Troubleshooting

- **Web app empty / blank at :8080** — that's the *app* (the dashboard at `:8000` is the old console,
  not the app). If it stays on the dark splash, check `tail -n 40 logs/app_web.log` for the build error.
- **"data is empty"** — the app can't reach the brain. Check **Settings → Test connection** (`brain: ok`)
  and `tail -n 30 logs/brain.log`.
- **Desktop shows offline after running the script** — only one brain can own `:8000`; the script now
  reuses an existing brain. Use `OPEN_DESKTOP=0 ./phase2_up.sh` if you start the desktop yourself.
- **Live suite fails off your Mac** — the sandbox has no network to Klaviyo/Veeqo + the engine isn't
  logged in; run it on your Mac.
