Odin — how everything connects

third party → anchor → your machine → agents → Klaviyo/Veeqo → webhook back

the pipeline
🌐

1 · Third party / your remote app

An outside caller (or odin_app abroad) wants an answer from a local project.

POST /anchor/v1/requestssends X-API-Key, project (identifier email-klaviyo), prompt, webhook_url
⚓

2 · Anchor (:9100 → VM in prod)

Authenticates, queues it, returns a unique request_id.

GET /anchor/v1/poll (X-API-Key)your machine pulls the task — never handed out twice
🖥️

3 · Local machine (poller)

Pulls the task over HTTP and runs the real orchestration.

CTO → assigns the agent → team works
🧠

4 · Brain + agents (Email / Shipping)

The project's CTO + agent produce the answer, grounded in live data.

read-only GET — never writes to your accounts
🔌

5 · Klaviyo / Veeqo

Real numbers: 50 flows (28 live / 22 draft) · 26 orders this week.

result flows back → POST /requests/{id}/result
📨

6 · Webhook → ack → FINISHED

Anchor POSTs to your webhook_url (the :9300 receiver); a 2xx reply = acknowledged → finished.

the details

✉️ Klaviyo (Email)

What: email/SMS marketing automation — "flows" (automated journeys) + campaigns.
Connect: oth/.cred → KLAVIYO_API_KEY=pk_…, KLAVIYO_BASE_URL=https://a.klaviyo.com/api, KLAVIYO_API_REVISION=2025-01-15; header Authorization: Klaviyo-API-Key <key>.
Project: new → type "Email specialist" → Email agent. id email-klaviyo.
Agent: any endpoint via call(); read-only flows_summary() → 50 flows (28/22). File server/integrations/klaviyo.py.

📦 Veeqo (Fulfillment)

What: inventory + shipping/fulfillment — orders, shipments, carriers.
Connect: oth/.cred → VEEQO_API_KEY=Vqt/…, base https://api.veeqo.com, header x-api-key.
Project: new → type "Fulfillment Provider" → Shipping agent. id shipping-veeqo.
Agent: orders, shipments, carriers; read-only orders_summary() → 26 orders this week. File server/integrations/veeqo.py.

⚓ Anchor Connect

Why: your machine has a dynamic IP behind NAT — unreachable. The anchor on the VM is the stable authenticated front door; your machine only calls out to it.
Endpoints: POST /requests, GET /requests/{id}, /ack, GET /poll, POST /requests/{id}/result, admin/*.
Auth: X-API-Key = ANCHOR_API_KEY. Ports: 9100 anchor · 9300 webhook receiver.
Lifecycle: queued → sent_to_local → processing → response_received → webhook_sent → acknowledged → finished (+ ack_pending / failed / cancelled).
Prod: point anchor URL at the VM, TLS on 443, rotate keys, sign webhooks — only the base URL changes.
